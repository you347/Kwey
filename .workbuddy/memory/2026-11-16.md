## 失效 token 导致脉冲 401 的回归修复（前端自愈）
- 回归根因：上一轮给 bootstrap 加了「本地重签前吊销旧 local-ui token」，但用户浏览器 localStorage 里仍存着已吊销的旧 token；app.js 判断「有 token 就不 bootstrap」→ 所有请求一直带废 token → pulse 报「访问 token 无效」。上一轮用全新浏览器 context 测试，未覆盖此真实场景。
- 复现：Playwright add_init_script 预置 `localStorage['kwey.agent.token']='STALE_TOKEN_12345'`，实测 pulse 401 且不自愈。
- 修复（api.js 请求层统一自愈）：抽出 sendOnce()；request() 遇 401 且非 bootstrap 自身时调 renewToken() 并**重放原请求一次**；renewToken 用模块级 `renewing` Promise 合并并发 401（避免多个请求各自 bootstrap 互相吊销）；导出 renewToken 供 agentlink.js 的 agentFetch 复用（它也加了同样的 401 重放）。
- 验证：预置废 token 场景——pulse 自动恢复为正常统计、provider-config 可读、连续刷新稳定、无 JS 异常；bootstrap 观察 1–2 次（多来自并发启动路径，功能无害，未过度追查）。

## 静态资源缓存导致"改了看不到"治本修复
- 用户反复看到旧界面（大图标、脉冲 401、chat 未配置 Provider），根因是浏览器缓存旧 CSS/JS；换 index.html 的 ?v= 参数不够——CSS/JS 的 URL 没变仍走缓存。
- 尝试 `StaticFiles(headers=...)` 失败（当前 Starlette 版本不支持该参数）→ 改用 `@app.middleware("http")` 给 `/static/*` 与 `/` 响应加 `Cache-Control: no-cache, no-store, must-revalidate`（API 路径不受影响）。实测三处静态资源均带新头，API 无头。
- 验证：全新 URL `?v=3` + no-cache 下设置页图标 16×16、导航项 33px、无 JS 异常；全量 pytest 840 passed / 5 skipped。
- 经验：本地桌面软件静态资源应禁强缓存；服务重启≠浏览器刷新，调试时优先怀疑缓存。
