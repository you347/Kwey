## F2 自动推送：应用内绑定远程仓库（用户质疑「为什么不在产品内部设置」后补齐）

### 背景
用户问「git 远程仓库有没有绑定」→ 实际查得 demo-vault 有 `.git` 但**零 remote**，`.kwey/autopush.json` 未生成，配置默认 `branch=main` 而仓库是 `master`。
随后用户质疑为什么产品内部不能手动绑定地址。承认这是设计过度：「不存凭据」被误当成「不给入口」。

### 实现
- `app/vault/autopush.py`
  - `_check_remote_url()`：只收 https/http/ssh/git/file 与 `git@host:path`；拒空、超长(500)、空白/控制字符、`-` 开头；http(s) 内嵌 userinfo → 返回 warning（不阻断），ssh 的 `git@` 不误报。
  - `bind_remote(url, name="origin", replace=False)`：`git remote add` / `set-url`，地址只写 `.git/config`；同名已存在且未允许替换 → ValueError；成功后把配置 `remote` 名同步。
  - `list_remotes()`（解析 `git remote -v`，区分 fetch/push）、`current_branch()`（`rev-parse --abbrev-ref HEAD`，分离 HEAD 返回空）、`repo_exists`。
  - **默认 branch 改为 `""` = 跟随当前分支**；`_effective_branch()` 配置优先 → 当前分支 → 兜底 main；`_pipeline` 与 `status()` 均使用（新增 `effective_branch` 字段）。
- `app/api/routes_autopush.py`：新增 `GET /remotes`、`POST /bind`（400 走统一信封）。
- `static/js/settings/schema.js`：同步卡新增「仓库地址」+「绑定仓库」行；远端 text→select；分支 placeholder 改为「留空 = 当前分支」。
- `static/js/autopush.js`：动态填充远端下拉（未绑定标注）、绑定提示（未绑/已绑/无 git/无仓库）、绑定按钮走 document 委托（DOM 重建不失效）、Enter 直接绑定、状态行显示推送分支。
