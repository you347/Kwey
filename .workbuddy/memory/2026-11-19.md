**Verbot 架构事实（用户提供，别再猜）**
- 独立长期运行的多服务栈：FastAPI :8000（LangGraph/工具/WS）+ Spring Boot :8082（业务/鉴权/数据）+ Vite :5175（UI，Tauri 只加载页面）。`scripts/stack.ps1` 分别启动，Rust 壳不托管 Python/Java。→ **不存在「Kwey spawn Verbot」的生命周期模型**（且缺 Java/MySQL/Redis 依赖）。
- **无 MCP**：依赖无 `mcp`/`langchain-mcp-adapters`，全仓零 JSON-RPC；工具层是固定进程内注册表（`app/tools/registry.py`，8 个 callable），无远程工具发现层。
- **无 OpenAI 兼容服务端**：只有 `/health`、`/api/v1/**`（Java→Python，`X-Internal-Key`）、`/api/v1/agents/draft`、asr/tts/ws。Verbot 是 OpenAI 协议的**客户端**（`langchain_openai.ChatOpenAI` 连百炼）。
- 例外：`scripts/local-llm.ps1` 起 llama.cpp `:8090`，有真 `/v1/chat/completions`，但那是裸模型，不经 Agent 图/工具/记忆，不算 Verbot 接管。
- 若要 Verbot 接管 Kwey 的 AI：薄 facade 绕开 Agent 能力（等价于直连百炼，多一跳）；走专用 REST（`/api/v1/integrations/kwey/...`）更干净，但 Verbot 是「异步任务 + WS 事件」，Kwey Provider 是同步 chat，语义不匹配 → **现阶段不做反向委派**。

**结论：单向链路** Verbot → Kwey（REST 优先，不做 MCP）。Verbot 启动拉 `/api/agent/contract` 拿全量 schema，裁 3~5 个注册进自己的 registry，等价手工版 MCP，比补 MCP client 便宜。

## Verbot 联调回执（2026-11-20）：FTS 连字符 bug 修复

**Verbot 侧已交付**：单向链路跑通，REST `/api/agent/tool` + 契约 v1，注册 5 个工具（search/read/write/append/create），token `name=verbot` `role=write`，明文只在 Verbot `ai-python/.env`。

**Verbot 报的现象（真 bug，已修）**：`search(query="PET-KWEY-SMOKE", mode="fts")` 返回 0 hits，但 `query=""` 能浏览、`query="Kwey"` 能命中。

**根因**：查询侧 `build_match_terms` 用 `[^\w]+` 把非 word 字符**删掉再粘合**，`PET-KWEY-SMOKE` → `PETKWEYSMOKE*`；而索引侧 FTS5 `unicode61 remove_diacritics 2` 把连字符当分隔符，实际 token 是 `pet`/`kwey`/`smoke` → 永不匹配。同类问题也影响下划线（`foo_bar`）和点号（`v1.2.3`），因为 `\w` 含 `_`。
**修复**：`_ASCII_TERM_RE` → `_ASCII_SPLIT_RE = re.compile(r"[\W_]+")`，ASCII 分支改为切分成多个词各自加 `*`，与 unicode61 的切分规则对齐。
**验证**：`build_match_terms(["PET-KWEY-SMOKE"]) == ["PET*","KWEY*","SMOKE*"]`；端到端建 `_probe/hyphen-check.md` 后 `mode=fts` total=1 命中；中文「欢迎」total=2 无回归。`tests/test_api_search.py` 追加 `TestHyphenatedTokens` 4 例（14 passed）。

**审计核对**：`GET /api/agent/audit?actor=verbot` 返回 8 条，路径全在 `_verbot_probe/`：create/update/append/delete 各阶段齐全，归因准确。
**契约核对**：Verbot 使用的 5 工具 required/props 与 `registry.contract()` 完全一致，v1 无漂移。
