# Kwey 产品需求文档（PRD）

> 版本：v1.0 ｜ 日期：2026-11-12 ｜ 撰写：许清楚（产品经理）
> 上游依据：`DESIGN.md`（产品定位、技术栈、功能池、Agent 连接规格、里程碑）
> **本轮开发范围 = M1 里程碑：P0 全部 13 项。P0 之外的需求（P1/P2/F1-F4）全部延后，本 PRD 仅登记优先级，不进入本轮实施。**

## 1. 产品定位

Kwey 是一款**本地优先、文件为源、Agent 原生**的个人知识库桌面软件（对标 Obsidian）：

- **本地优先**：数据全部存于用户本地，磁盘 Markdown 文件夹是唯一事实源。
- **文件为源**：SQLite（FTS5 / 图）与 Chroma 仅做索引，全部可重建；用户可以用任何编辑器打开笔记。
- **Agent 原生**：与用户自建 agent 系统双向连接（外部 agent 经 MCP/REST 读写库；内嵌 agent 整理任务经统一写路径落盘）。

技术栈以 `DESIGN.md` 已定稿方案为准（Python 3.13 / FastAPI + uvicorn / pywebview / markdown-it-py + python-frontmatter / watchfiles / SQLite FTS5；Chroma 与 MCP 属 M2/M3），本 PRD **只引用、不另提选型**。

## 2. 产品目标

| # | 目标 | 衡量标准 |
|---|------|----------|
| G1 | M1 交付一个可日常使用的本地 Markdown 知识库内核 | 13 项 P0 全部通过验收标准；对 500+ 笔记的既有 Obsidian vault 打开后编辑/搜索/双链行为正确 |
| G2 | 双向链接体验达到 Obsidian 同档水准 | `[[双链]]`/别名/嵌入在预览中可点击跳转；改名/移动笔记后全库链接自动更新且 0 断链 |
| G3 | 检索响应满足"随手查"节奏 | 1000 笔记规模下全文搜索（含 path:/tag:/file: 操作符）结果返回 ≤ 200ms（本地基准） |
| G4 | 磁盘文件即界面，索引可重建 | 手动删除 `.kwey`/索引文件后重启应用，功能完整恢复且内容零丢失 |
| G5 | 为 M2 Agent Link 留好接口 | Vault Service 统一写路径、事件总线雏形在 M1 内成型（UI 与未来 agent 调用共用同一服务层） |

## 3. 目标用户与三类使用身份

**目标用户**：有知识管理习惯的个人（学生、研究者、开发者、写作者），主要在 Windows 桌面环境工作，笔记以 Markdown 组织。

三类使用身份：

1. **独立知识库用户**：直接操作界面，编辑、双链、搜索、管理文件——M1 的全部服务对象。
2. **外部 agent 系统接入者**：把自己的 agent（MCP / REST/WS 客户端）连到 Kwey，将 Kwey 当作可检索、可读写的长期记忆库——M2 落地，M1 预留接口。
3. **Kwey 内嵌 agent 整理者**：在 Kwey 内发起整理任务（建链、打标、归类），agent 返回结构化 ops，用户 diff 确认后落盘——M2/M4 落地（F1/F3/F4），M1 预留统一写路径。

## 4. 用户故事

### 身份① 独立知识库用户

- 作为独立知识库用户，我希望打开本地任意文件夹作为 vault 并自动建立索引，以便用 Kwey 管理我已有的 Markdown 笔记。
- 作为独立知识库用户，我希望在编辑器中写 `[[双链]]`、`[[a|别名]]` 和 `![[嵌入]]`，以便笔记之间互相引用、一个笔记可聚合展示另一笔记内容。
- 作为独立知识库用户，我希望在反向链接面板看到"谁链接了我"和未链接提及，以便补链、发现关联。
- 作为独立知识库用户，我希望用全文搜索加 `path:`/`tag:`/`file:` 操作符快速定位笔记，以便在大量笔记中一秒找到目标。
- 作为独立知识库用户，我希望在文件树里新建/改名/移动/删除笔记时全库链接自动更新，以便整理文件不断链。

### 身份② 外部 agent 系统接入者（M2，本期延后）

- 作为外部 agent 接入者，我希望通过 MCP 工具（kwey.search / kwey.read / kwey.write 等）检索和读写库，以便把我自建 agent 的长期记忆放进 Kwey。
- 作为外部 agent 接入者，我希望订阅库变更事件（WS/SSE），以便 agent 与 vault 实时保持同步。
- 作为外部 agent 接入者，我希望写入操作自动产生 git 快照并按 token 分级鉴权，以便安全回滚、权限可控。

### 身份③ Kwey 内嵌 agent 整理者（M2/M4，本期延后）

- 作为内嵌 agent 整理者，我希望选中笔记发起"自动建链/打标"整理任务，以便 AI 帮我构建图谱（F1）。
- 作为内嵌 agent 整理者，我希望 agent 的所有修改以结构化 ops + diff 确认的形式呈现，以便我逐条批准后才落盘。
- 作为内嵌 agent 整理者，我希望我的个人记忆以普通 md 文件存在 `.kwey/memory/` 中且可直接编辑，以便记忆对我完全透明可控（F3）。

## 5. 需求池（含验收标准）

### P0 — 最小可用（M1，本轮开发范围）

| # | 功能 | 验收标准 |
|---|------|----------|
| P0-1 | Vault 打开/扫描/增量索引 | Given 一个含 md 文件的文件夹，When 用户选择打开，Then 完成 frontmatter/链接/标签解析建索引；此后外部改动文件（经 watchfiles 防抖）仅增量更新受影响索引，不触发全库重扫 |
| P0-2 | Markdown 编辑器：源码 + 实时预览 | Given 一篇笔记，When 在源码模式输入，Then 可切换到实时预览且 wikilink/嵌入/标签/标题/代码块均正确渲染；双向切换光标位置合理保持 |
| P0-3 | `[[双链]]`（含别名）+ 嵌入 `![[...]]` | Given 输入 `[[目标]]`、`[[目标\|别名]]`、`![[目标]]`，Then 预览中分别渲染为链接/别名链接/内嵌内容块；点击可跳转到目标笔记（目标不存在时创建该笔记）；嵌入在源笔记变更后预览同步更新 |
| P0-4 | 反向链接面板 + 未链接提及 | Given 当前笔记被 N 篇笔记链接，Then 面板列出全部反向链接（点击可跳转）；Given 库中存在包含本笔记标题但未建链的文本，Then "未链接提及"区列出并可一键转为双链 |
| P0-5 | 嵌套标签 `#a/b` + 标签面板 | Given 笔记含 `#a/b` 标签，Then 标签面板按层级树展示、点击列出对应笔记；frontmatter tags 与行内标签合并统计 |
| P0-6 | 全文搜索 + 操作符 | Given 1000 笔记，When 搜索 `关键词`、`path:子目录 词`、`tag:a/b 词`、`file:名`，Then FTS5（BM25）返回按相关度排序结果，支持结果内高亮与点击跳转 |
| P0-7 | 文件树：新建/改名/移动/删除 + 改名自动更新全库链接 | Given 笔记 A 被 5 处双链引用，When 将 A 改名或移动，Then 全部 5 处链接路径自动更新且库内 0 断链；删除进 `.trash/`，附件目录结构保持可配置 |
| P0-8 | 快速切换器 Ctrl+O | Given 输入笔记名模糊片段，Then 浮层按相关度列出候选（≤300ms），Enter 打开、方向键选择 |
| P0-9 | 命令面板 Ctrl+P | Given 输入命令片段，Then 列出全部可执行命令（模糊匹配、含快捷键提示），Enter 触发对应动作 |
| P0-10 | frontmatter 属性 | Given 笔记含 YAML frontmatter（title/tags/created/自定义），Then 解析后在属性区展示并可编辑，保存后写回原文件且格式合法、其余正文不受影响 |
| P0-11 | 多标签页 | Given 已打开多个笔记，Then 中央区以标签页呈现，可切换/关闭；关闭应用重启后可恢复上次标签页（或至少最后激活页） |
| P0-12 | 附件：粘贴/拖入图片存 attachments/ | Given 在编辑器内粘贴或拖入图片，Then 文件自动复制到 `attachments/`（路径可配置）并在光标处插入相对链接，预览可正常显示 |
| P0-13 | 暗色/亮色主题切换 | Given 设置页切换主题，Then 全应用（编辑器/面板/浮层）即时生效，选择持久化到 settings.json |

## 6. 界面结构设计（文字版线框）

主窗口为经典三栏布局，顶部标签栏，底部状态栏。

```
┌──────────────────────────────────────────────────────────────┐
│ 标题栏（应用名 / vault 路径）          [主题切换] [设置]       │
├────────────┬──────────────────────────────────┬──────────────┤
│ 左侧边栏    │ 中央多标签编辑器                  │ 右侧面板      │
│ · 文件树    │  [标签1][标签2][标签3][+]         │ · 反向链接    │
│   (P0-1,7) │  ┌──────────────────────────┐    │   (P0-4)     │
│ · 标签面板  │  │ 源码 | 预览（模式切换）    │    │ · 未链接提及  │
│   (P0-5)   │  │ CodeMirror 6 编辑区      │    │   (P0-4)     │
│            │  │                          │    │              │
│            │  │                          │    │ （M3 增补：   │
│            │  │                          │    │  大纲/本地图谱）│
│            │  └──────────────────────────┘    │              │
├────────────┴──────────────────────────────────┴──────────────┤
│ 状态栏：字数 / 保存状态 / 索引状态                            │
└──────────────────────────────────────────────────────────────┘
浮层：Ctrl+P 命令面板（P0-9） · Ctrl+O 快速切换器（P0-8）
```

各区域明细：

- **左侧边栏**（可折叠）：① 文件树——新建/改名/移动/删除（P0-1 打开 vault 后展示、P0-7 文件管理）；② 标签面板——嵌套标签层级树（P0-5）。
- **中央多标签编辑器**（P0-11）：每个标签内为源码（CodeMirror 6）/ 实时预览切换（P0-2），支持双链/嵌入渲染与点击跳转（P0-3）；粘贴/拖入图片插入附件链接（P0-12）。
- **右侧面板**：反向链接 + 未链接提及（P0-4）。M3 增补大纲（P1-15）与本地图谱（P1-14）入口。
- **命令面板 Ctrl+P**（P0-9）与**快速切换器 Ctrl+O**（P0-8）：居中浮层、模糊搜索、键盘导航。
- **设置页**：主题切换（P0-13）、附件目录路径、vault 管理入口；为 M2/M3 预留 Provider、快捷键、向量检索配置区块（本期灰置或隐藏）。

## 7. 非目标（本轮不做）

- 云同步服务（官方同步/Kwey Sync）——P2-30 文件级同步与 F2 git 推送均不在本轮。
- 移动端（iOS/Android）。
- 协作编辑 / 多人实时同步。
- npm 构建链前端——前端为 HTML/CSS/JS + CodeMirror 6 直引，不引入 Node 构建工具链。
- P0 之外的一切功能（P1/P2/F1-F4 全部延后；Chroma 与 MCP 属 M2/M3，本轮不实现，仅保证架构分层不返工）。

## 8. 待确认问题（假设，不阻塞开发）

1. 假设 vault 根目录选择与切换在首次启动引导中完成，暂不做多 vault 并存管理；若需要，M3 再补。
2. 假设断链（目标文件被删）在预览中渲染为虚线/红色链接、点击提示创建——具体视觉待设计稿确认。
3. 假设重启后恢复全部上次打开的标签页；若实现成本高，降级为仅恢复最后激活页。
4. 假设附件相对链接以 vault 根为基准解析；wiki 式无路径链接（`![[图.png]]` 按文件名全局解析）是否支持，待 M1 内定。
5. 假设 1000 笔记规模为 M1 性能验收基准；更大规模（1 万+）留到 M3 配合向量索引一起压测。
6. 假设事件总线雏形（watchfiles → 广播）在 M1 内部成型但不对外暴露 API，M2 才开放给 agent。

## 9. 环境备注

- 操作系统：Windows；Python 3.13.14；git 可用；pip 需通过 `python -m pip` 调用。
- 打包（PyInstaller 单 exe + WebView2）不在 M1 验收范围内，M1 以本机开发环境运行为准。
